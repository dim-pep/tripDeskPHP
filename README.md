# TripDesk

**TripDesk** — REST API для управления корпоративными командировками. Проект позволяет создавать заявки на поездки, просматривать их, редактировать до согласования и управлять их статусами.

Проект разрабатывается на PHP с использованием MySQL. Архитектура разделяет бизнес-логику, прикладные сценарии, инфраструктуру хранения данных и HTTP-слой.

## Возможности

- Создание заявок на командировки.
- Получение списка всех заявок.
- Получение отдельной заявки по ID.
- Редактирование заявок в статусе `pending`.
- Согласование заявок.
- Отклонение заявок.
- Отмена заявок.
- Проверка бизнес-правил и допустимых переходов между статусами.
- Сохранение данных в MySQL через PDO.
- Обработка ошибок и возврат соответствующих HTTP-статусов.
- Автоматизированные unit- и integration-тесты с PHPUnit.

### Назначение слоёв

**Domain**

Содержит основные бизнес-сущности, их состояние и правила. Например, сущность `Trip` самостоятельно контролирует допустимые операции над заявкой и переходы между статусами.

**Application**

Содержит прикладные сценарии. `TripService` координирует работу доменной модели и репозитория.

**Infrastructure**

Отвечает за технические детали реализации, в том числе подключение к MySQL и сохранение данных через PDO.

**Presentation**

Обрабатывает HTTP-запросы, маршрутизацию, контроллеры и формирование JSON-ответов.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/dim-pep/tripDeskPHP.git
cd tripDeskPHP
```

### 2. Установка зависимостей

```bash
composer install
```

### 3. Настройка окружения

Создай локальный файл `.env` на основе примера:

```bash
cp .env.example .env
```

При необходимости проверь параметры подключения к базе данных:

```dotenv
APP_ENV=local
APP_DEBUG=true

DB_HOST=127.0.0.1
DB_PORT=3307
DB_NAME=tripdesk
DB_USER=tripdesk
DB_PASSWORD=secret
DB_ROOT_PASSWORD=root
```

Не публикуй файл `.env` в GitHub: он содержит локальные настройки и учётные данные.

### 4. Запуск MySQL

```bash
docker compose up -d
```

Docker Compose запустит MySQL 8.4 с сохранением данных в Docker volume.

### 5. Применение миграции

При наличии установленного клиента MySQL выполни:

```bash
mysql -h 127.0.0.1 -P 3307 -u tripdesk -p tripdesk < database/migrations/001_create_trips_table.sql
```

Введи пароль пользователя базы данных, указанный в `.env`.

Миграция создаёт таблицу `trips` для хранения заявок на командировки.

### 6. Запуск HTTP-сервера

```bash
php -S localhost:8000 -t public
```

API будет доступно по адресу:

```text
http://localhost:8000
```

## REST API

Базовый путь:

```text
/api/trips
```

| HTTP-метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/api/trips` | Получение списка заявок |
| GET | `/api/trips/{id}` | Получение заявки по ID |
| POST | `/api/trips` | Создание заявки |
| PUT | `/api/trips/{id}` | Обновление заявки |
| POST | `/api/trips/{id}/approve` | Согласование заявки |
| POST | `/api/trips/{id}/reject` | Отклонение заявки |
| POST | `/api/trips/{id}/cancel` | Отмена заявки |

### Создание заявки

**Запрос:**

```http
POST /api/trips
Content-Type: application/json
```

```json
{
  "city": "Berlin",
  "ticket_price": 250,
  "hotel_price": 120,
  "nights": 3
}
```

**Успешный ответ:** `201 Created`.

В ответе возвращается созданная заявка с присвоенным ID и рассчитанной общей стоимостью.

### Получение списка заявок

```http
GET /api/trips
```

**Успешный ответ:** `200 OK`.

### Получение заявки по ID

```http
GET /api/trips/1
```

### Обновление заявки

```http
PUT /api/trips/1
Content-Type: application/json
```

```json
{
  "city": "Prague",
  "ticket_price": 300,
  "hotel_price": 150,
  "nights": 2
}
```

Обновлять можно только заявки в статусе `pending`. Все редактируемые поля должны присутствовать в запросе.

### Согласование заявки

```http
POST /api/trips/1/approve
```

### Отклонение заявки

```http
POST /api/trips/1/reject
```

### Отмена заявки

```http
POST /api/trips/1/cancel
```

## Статусы заявок

| Статус | Описание |
|---|---|
| `pending` | Заявка ожидает рассмотрения |
| `approved` | Заявка согласована |
| `rejected` | Заявка отклонена |
| `cancelled` | Заявка отменена |

Переходы между статусами контролируются доменной моделью. Недопустимые операции приводят к ошибке бизнес-правил.

## Обработка ошибок

API возвращает JSON-ответы и использует стандартные HTTP-статусы:

| Код | Описание |
|---|---|
| 200 | Запрос успешно выполнен |
| 201 | Ресурс успешно создан |
| 400 | Некорректный запрос |
| 404 | Ресурс или маршрут не найден |
| 405 | HTTP-метод не поддерживается для маршрута |
| 409 | Конфликт с бизнес-правилами |
| 422 | Ошибка валидации входных данных |
| 500 | Внутренняя ошибка сервера |

## Тестирование

Для запуска автоматизированных тестов выполни:

```bash
vendor/bin/phpunit
```

Тесты разделены на две группы:

**Unit-тесты**

Проверяют:
- бизнес-логику сущности `Trip`;
- допустимые переходы между статусами;
- валидацию данных;
- поведение `TripService`;
- работу HTTP-маршрутизатора.

**Integration-тесты**

Проверяют взаимодействие `PdoTripRepository` с MySQL:
- создание записей;
- получение заявок;
- получение списка заявок;
- обновление данных;
- обработку отсутствующих записей.

Для интеграционных тестов требуется запущенный MySQL с применённой миграцией. До настройки отдельной тестовой базы запускай их только на локальной базе без ценных данных.
